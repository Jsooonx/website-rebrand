# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Nexora is a reusable demonstration site for Stackframe, a library of
reference-informed website prompts. Its audience is intentionally unconstrained
so the example can demonstrate a broadly adaptable SaaS rework workflow.

## Product Purpose

Nexora demonstrates how Stackframe can turn a visual reference into an
original, usable website concept without reusing the reference's brand, copy,
runtime assets, or implementation.

The displayed product is a fictional AI workspace for operational teams. It
portrays a workflow for asking work questions, checking source context,
preparing accountable actions, and reviewing recurring patterns.

## Positioning

The project is an original-work benchmark for reference-informed rebranding:
it preserves an approved structural direction while replacing product truth,
brand identity, UI content, and visual assets with original material.

## Operating Context

Stackframe uses Nexora as a prompt-library example. Future changes should keep
the distinction between a supplied visual reference and the original Nexora
brand, content, and implementation explicit.

## Reference workflow

- Reference mode: `Rework mode`.
- Reference status: supplied paid-template screenshots used as private quality
  context.
- Public distribution: intended as an original Stackframe template example.
- The reference informed the initial section conversations, but the final
  section hierarchy, visual world, assets, copy, and implementation are
  original to Nexora.

## Capabilities and Constraints

- The landing page demonstrates Collect, Validate, and Act stages through a
  fictional AI workspace.
- It is implemented as a Vite, React, and TypeScript website.
- References guide the approved design conversations, but their proprietary
  brand, copy, assets, logos, and implementation must not be reused.
- No claims on the page should imply that Nexora is a live AI product.

## Brand Commitments

- Name: Nexora.
- Nexora is a fictional brand and should be presented in title case in
  marketing copy unless an intentionally compact product-UI label requires a
  different treatment.
- The site must remain clear that it is an original, reference-informed
  demonstration for Stackframe.

## Evidence on Hand

- All product records, company names, testimonials, portraits, metrics, plan
  details, integration marks, and outcomes are fictional.
- The site includes a visible fictional-content disclosure.
- No real customer evidence, case studies, pricing commitments, or product
  availability claims are available.

## Product Principles

1. Treat references as structural direction, not runtime source material.
2. Keep brand, content, assets, and implementation original.
3. Make the fictional product concept legible in the first viewport.
4. Preserve clear disclosure when a claim or proof point is fictional.

## Accessibility & Inclusion

- Preserve semantic navigation, keyboard operation, visible focus, and
  reduced-motion alternatives.
- Keep touch targets usable on mobile and maintain readable text contrast.
